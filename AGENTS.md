# admin-site

<!-- Agents read this every session — every line costs context. Keep it current and concise. -->

HackIllinois' staff admin dashboard for admissions, events and check-in, notifications, email,
newsletters, the points shop, job postings, sponsors, attendance and attendee statistics.
Next.js 15 App Router; every page is a client component (`"use client"`). The site has no
backend or database of its own. All data comes from the **Adonix** API
(`https://adonix.hackillinois.org`) through a TypeScript SDK generated from Adonix's OpenAPI
spec. Built with OpenNext and deployed as a Cloudflare Worker (`wrangler.jsonc`,
`open-next.config.ts`).

## Repo Structure

- `app/` — One folder per admin page (`app/<route>/page.tsx`), plus `app/lib/api/` data helpers
- `components/` — Shared UI (NavBar, Loading, SelectField, Unauthorized, ...)
- `util/` — API client setup and auth (`api-client.ts`), nav routes (`routes.ts`), email helpers
- `generated/` — Adonix SDK generated by `@hey-api/openapi-ts`. **Never edit by hand**
- `public/` — Static assets; `public/email/` holds artwork referenced by sent emails
- `tests/` — `node:test` unit tests for pure `util/` logic
- `.github/workflows/` — CI: build, lint, format check

## Commands

Use Node 22 (the version CI runs).

```bash
npm install                # Install dependencies
npm run dev                # Local dev server (Turbopack) on :3000
npm run build              # Production build (CI runs this)
npm test                   # Unit tests in tests/*.test.ts (CI does NOT run this)
npm run lint               # ESLint (CI runs this)
npm run format:check       # Prettier check (CI runs this)
npm run format             # Prettier write
npm run update-adonix      # Regenerate generated/ from the live Adonix OpenAPI spec
```

## Environment

- `NEXT_PUBLIC_ADONIX_BASE_URL` — Optional. Adonix origin, e.g. `http://localhost:3001` for a
  local Adonix; defaults to `https://adonix.hackillinois.org` (`util/hey-api.ts`)
- `NEXT_PUBLIC_EMAIL_ASSET_BASE_URL` — Optional. Public origin for email artwork when sending
  from a local server; defaults to the site's own origin (see [README](README.md))

## Rules

- **Before pushing:** `npm run lint`, `npm run format:check`, `npm test`, and `npm run build` must pass
- **Formatting:** Prettier only matches `*.{ts,js,cjs,json}`, so `.tsx` and `.scss` files are not
  checked. Match the surrounding style (4-space indent, no semicolons) by hand
- **No login:** Agents can't sign in locally. Most pages need a `@hackillinois.org` staff
  account through Adonix Google login. Verify changes with `npm run build`, `npm test` and by
  reading the code, and list any page that still needs a manual check in the PR test plan
- **No deploys:** Never deploy or run `wrangler` / `opennextjs-cloudflare` commands. Deployment
  is handled outside this repo
- **API calls:** Use the generated services (`StatisticService`, `EventService`, ...) wrapped in
  `handleError` from `util/api-client.ts`. No raw `fetch` to Adonix
- **Generated code:** Change `generated/` only via `npm run update-adonix`; commit the result
- **New page:** Add `app/<route>/page.tsx` and register it in `util/routes.ts` so it appears in the NavBar
- **Permissions:** Gate role-restricted UI with `useRoles()`; Adonix enforces roles server-side
- **Types:** `any` is a lint error. Prefer `.tsx`/`.ts`; the `.jsx` components are legacy
- **Styling:** CSS Modules (`*.module.scss`) per page/component; theme colors live in `app/constants.scss`
- **Email artwork:** Never rename or delete files in `public/email/` — sent emails link to them
- **AGENTS.md:** Update this file when commands, structure or architecture change

## Architecture

### Component Map

| Component         | Responsibility                                                         | Key Files                                        |
| ----------------- | ---------------------------------------------------------------------- | ------------------------------------------------ |
| Root layout       | Calls `setupClient()` once, renders the NavBar and sets the page title | `app/layout.tsx`                                 |
| Pages             | One feature per route; fetch, render and mutate Adonix data            | `app/<route>/page.tsx`                           |
| Page data helpers | Non-trivial fetching and aggregation kept out of page components       | `app/lib/api/*.ts`                               |
| API client & auth | Interceptors, Google login redirect, `handleError`, `useRoles`         | `util/api-client.ts`                             |
| SDK config        | Adonix base URL, `credentials: "include"` (cookie auth)                | `util/hey-api.ts`                                |
| Generated SDK     | Typed services and models for every Adonix endpoint                    | `generated/` (from `openapi-ts.config.ts`)       |
| Navigation        | Route list (path, label, icon) that drives the NavBar                  | `util/routes.ts`, `components/NavBar/`           |
| Email             | Template wrapper, image library, recipient resolution                  | `util/email-*.ts`, `app/email/`, `public/email/` |
| Metadata          | Reads the `adonix-metadata` GitHub repo, cached in sessionStorage      | `util/metadata.ts`                               |
| Tests             | `node:test` unit tests for pure logic                                  | `tests/*.test.ts`                                |

### Dependency Rules

- `generated/` is machine-written. Nothing edits it; it depends only on `util/hey-api.ts`.
- `util/` and `app/lib/` may import `generated/`. They must not import from `app/<route>/`.
- `components/` may import `util/` and `generated/` types. They must not import page modules.
- `app/<route>/` may import `components/`, `util/`, `app/lib/` and `generated/`. Pages do not
  import from other pages. Shared code moves to `components/`, `util/` or `app/lib/`.
- Code under `tests/` imports only modules that don't touch React or the DOM. Keep testable
  logic in plain `util/` functions.
- Imports use the `@/` alias, which maps to the repo root.
- Legacy: `components/Auth` and `components/AuthenticatedRoute` import a removed `util/api`
  module and are unused. Don't build on them. Use `util/api-client.ts` instead.

### Data Flow

1. On first render, `app/layout.tsx` calls `setupClient()`. This installs request and response
   interceptors on the shared hey-api client.
2. A page calls an SDK method, e.g. `StatisticService.getStatistic({ query })`. The browser
   sends the Adonix session cookie (`credentials: "include"`).
3. If Adonix returns `TokenInvalid`, `TokenExpired` or `NoToken`, the client redirects to
   `${baseUrl}/auth/login/google?redirect=<current URL>`. Adonix sends the user back with a
   session.
4. `handleError(result)` returns `data`, or raises an `alert` and throws on any other error.
5. `useRoles()` fetches `/auth/roles` so pages can hide controls (or show `<Unauthorized />`)
   for users without the needed role. Adonix still enforces authorization server-side.
6. `/` redirects to `/admissions` (`next.config.ts`).

### Key Decisions

| Decision                                              | Rationale                                                        |
| ----------------------------------------------------- | ---------------------------------------------------------------- |
| Generate the Adonix client with `@hey-api/openapi-ts` | Types stay in sync with the backend                              |
| Cookie-based auth via Adonix Google OAuth             | No tokens stored in the admin site. Roles come from Adonix       |
| All pages are client components                       | Auth cookie and role checks happen in the browser against Adonix |
| Email artwork served from `public/email/`             | Sent emails need stable public URLs                              |
